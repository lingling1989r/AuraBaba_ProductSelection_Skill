# 结果验证（gate）语义

## 为什么要有 gate

选品分析最容易出的问题不是算错，而是**结论跑在数据前面**：
先有立场，再找数字支撑。这套流水线用两道机制挡住它：

1. **结构上**：`analysis/` 的产物只有在 `data/` 通过校验后才会被检查。
   没有数据表，就写不出"通过"的阶段。
2. **数值上**：每个阶段有明确的阈值（样本量、观测期数、集中度……），
   达不到就是达不到，不允许"大致满足"。

## 判定结果长什么样

`pipeline.py check --stage S2` 会在 `analysis/gate_S2.json` 写：

```json
{
  "ok": false,
  "checked_at": "2026-09-15T00:31:12Z",
  "checks": [
    {"check": "table", "path": "data/02_trend_summary.csv", "ok": true,
     "detail": "rows=7 (min 3); missing_columns=none"},
    {"check": "at_least_one_survivor", "ok": true,
     "detail": "5/7 keywords classified as TREND"}
  ]
}
```

同一份结果也会写回 `state.json` 的 `stages.<S>.gate`，最终进 Excel 的 `13_阶段验证` sheet。

## 校验的四种类型

| 类型 | 含义 | 代码 |
|---|---|---|
| `file_exists` | 文件存在 | `_file_check` |
| `table` | CSV 列名齐全 + 行数达标（xlsx/html 只查非空） | `_table_check` |
| 命名断言 | 阶段特有的数值判断 | `g_s0` … `g_s7` |
| derived | 由前面几个阶段的表算出来的 | 见 `g_s4` / `g_s6` |

## 各阶段阈值一览

| 阶段 | 断言 | 阈值 | 为什么是这个数 |
|---|---|---|---|
| S0 | 至少一个一级源可用 | ≥1 | 全挂时应当停下，而不是硬凑报告 |
| S1 | 热词数 | ≥8 | 太少无法做趋势筛选 |
| S1 | 含 `identity` 类型词 | 必须有 | 防止把商品词当入口，那是红海 |
| S1 | 溯源完整 | 100% | 没有来源的数字不能进报告 |
| S2 | 观测期数 | ≥24 | 少于两年无法区分趋势与季节波动 |
| S2 | Trend 存活数 | ≥1 | **全为 Fad 是有效结论**，此时直接出报告说明"不该做" |
| S4 | 提及总数 | ≥100 | 样本量不够时占比无意义 |
| S4 | Top 痛点占比 | ≥20% | 达不到说明痛点分散，不构成可立项信号 |
| S5 | 月销售额 | ≥$1,000,000 | 盘子太小撑不起一个品牌 |
| S5 | 头部品牌集中度 | ≤70% | 高于此新品牌进不去 |
| S6 | `evidence_refs` 覆盖率 | 100% | 不允许出现无法回溯的评分 |

阈值集中在 `config.local.json` 的 `gate_defaults`，便于按品类调。
**调阈值必须在阶段分析笔记里写明为什么调**，否则下一轮读报告的人无法判断结论强度。

## 加一条新校验

1. 在 `pipeline.py` 里写一个 `g_<stage>(run) -> list[dict]` 函数，
   返回若干个 `{"check": "<名字>", "ok": bool, "detail": "..."}`。
2. 注册进 `GATES` 字典。
3. 把 key 加进对应 `STAGES[...]["gate"]` 列表。

保持校验函数**纯读**：只读文件、算指标、返回判定，不修改任何数据。

## 判定与状态流转

| 状态 | 含义 |
|---|---|
| `pending` | 未开始 |
| `running` | fetch 已发起 |
| `passed` | gate 全通过 |
| `failed` | gate 有未通过项 |

`check-all` 会把所有阶段重算一遍。**注意**：它不会因为 S7 未产出而失败 ——
`finalize` 之后跑一遍 S7 的 gate 即可闭环。

## 反模式（不要这样做）

- ❌ 手动改 `state.json` 让阶段变 `passed` —— 报告里的"阶段通过 n/N"就变成了假数据。
- ❌ 数据表缺列时新建一份只含表头的文件"占位" —— 行数校验会拦住，但别去试。
- ❌ 为了让 Trend 存活数达标而把 `trend_min_cagr_pct` 调到 0 ——
  这是把结论倒过来改数据，属于本流水线明确要防的行为。
- ❌ 报告与 Excel 数字不一致 —— 两者都只读 `data/*.csv`，所以只要不手改产物就不会不一致。
